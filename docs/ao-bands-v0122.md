# 0.12.2：地板上的跨屏横向暗带

日期：2026-11-02。

用户指出的横线是屏幕空间环境遮蔽（SSAO）错误产生的暗带。相机静止后仍存在。上一轮看到地砖贴图有重复便将地面问题归为材质平铺，未隔离 SSAO，判断不准确；贴图重复和此次跨屏横线是两件事。

## 定位与修复

使用 Sponza 的固定相机逐项隔离 TAA、AO、底色（含强制 LOD 0）、法线、阴影可见性、环境光与 RSM 间接光。在只输出 `gmAmbientOcclusion` 的诊断图中，地板上直接出现多条跨屏横向暗带，排除了砖缝/颜色贴图的干扰。

AO 在半分辨率目标上运行，但读取全分辨率、最近邻采样的深度。旧代码把任意 UV 处读到的深度，直接用这个 UV 还原三维位置；实际深度属于被选中的像素中心。半分辨率中心可能落在全分辨率像素边界，邻域法线和径向采样因此把平面误判成有凹凸与遮挡，形成明暗条带。

`fs_ao.sc` 现在先将中心以及每个径向样本的 UV 对齐到深度纹理 texel 中心，再读取深度并用同一坐标重建位置。保留原有半分辨率、采样数量、遮蔽强度、半径和接触阴影。同步生成 DXBC / ESSL 字节码。无资源格式或游戏模块 ABI 变化，无需调整地板贴图或游戏自定义材质 shader。

## 验证

- 新增实际 GPU 平面回归：无纹理、无其他遮挡物的平面，在俯角 22° / 40° / 65°、渲染比例 1 / 0.73 下比较开关 AO 的亮度。旧 shader 在第一个用例产生最大 13/255 的错误，测试失败；修复后六个用例最大差异均为 0。
- 原有接触区域变暗、直射光不受 AO 影响、TAA 静止收敛等 GPU 合约继续通过。
- 同相机的 Sponza AO 原始输出中横线消失，柱脚接触遮蔽保留；完整着色输出也已对照。
- 本地 Release 全量构建、20 项 CTest 通过（7.34 秒）。DXBC 与 ESSL 编译通过；运行验证为本机 D3D11，未声明移动真机验证。
- 同场景、同镜头统计：质量缓冲仍为 37,324,800 bytes，目标总容量仍为 94,619,648 bytes，draw calls 仍为 283。不增加纹理读取数量或渲染 pass；这里只确认资源和提交量，不将单帧 GPU 时间差当成性能提升。
