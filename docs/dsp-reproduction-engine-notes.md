## 制作过程

| 阶段 | 实际发现 / 决策 | 产物 |
| --- | --- | --- |
| 参考项目调查 | 原项目是生产网络节点画布，不是控制角色的瓦片地图；现有版本还含云账号、星系、空间站等大量扩展 | 固定源码提交，优先单机生产闭环 |
| 引擎接入 | SDK Frame 只有 inputX/inputY，无法完成节点选择、拖拽和拉线 | ABI 9 输入快照、Player / 编辑器统一坐标转换 |
| 动态界面 | 现有 UI 只提供静态控件和数值绑定，不能输出动态配方名、网络连线 | 有界 Canvas 命令缓冲，经 SceneView / bgfx 渲染 |
| 内容转换 | 直接运行 React / TS 不符合原生模块架构 | 构建期 Node 24 转换目录到 C++，Player 不读取 JSON / TS |
| 生产模拟 | 物流、在途货物、配方在制原料都必须具有唯一所有者 | 100 ms 固定模拟步、整数库存、原子预留、缺电与堵塞处理 |
| 存档 | 引擎快照不保存 System 私有状态 | 游戏侧显式二进制格式、版本/目录指纹/校验、验证后替换、临时文件原子写入 |
| 自动验证 | 原 CLI 无指针输入，也无法验证动态画布 | runtime.input、runtime.canvas、输入契约测试、原生 GPU 场景导出工具 |
| 原生画面检查 | 1600×900 自动渲染图布局清晰，初始 960×600 窗口缩字明显 | Player 按场景设计尺寸与桌面可用区计算初始大小 |
| 实机交互 | 制造弹窗会被背后的科技页按钮抢走点击 | 游戏侧增加模态输入隔离；列入交互回归 |
| 挂机行为 | Player 失焦时完全停止模拟 | Player 后台继续更新，后台等待间隔 100 ms，前台约 16 ms；最小化不提交渲染 |
| 回归检查 | 扩建时若直接增加数量，会让已预留的一批原料生成多台产物 | 游戏侧先退还在制输入再扩建，增加守恒测试 |

## 引擎问题清单

“已解决”只指本项目需要的具体能力，不代表整个相关子系统已经完备。

| ID / 优先级 | 证据与影响 | 本次处理 | 后续建议 / 验收条件 |
| --- | --- | --- | --- |
| E01 / P0 输入不足 | 原 `sdk/include/gm/game.hpp` 的 Frame 只有两个移动轴，工厂交互无法实现 | **已解决基本键鼠**：逻辑坐标、按住/按下/释放、滚轮、按键、焦点；两种宿主共用 `windows_game_input.hpp` | 输入动作映射、重新绑定、手柄/触屏仍未实现；把 Windows VK 约定替换为平台无关键码 |
| E02 / P0 固定步输入边界 | 低于一个模拟步的渲染帧会丢短点击；多次补帧又可能重复执行建造 | **已解决**：SceneRuntime 累积边沿，第一次 tick 消费，后续补帧只保留 held | 已有输入契约测试覆盖零步帧、三步补帧、重置；以后增加完整带时间/位置的事件队列，以支持同一渲染帧内的多次独立点击 |
| E03 / P0 动态游戏 UI | `BindingKind` 只有 NumberText / NumberBar / NumberChange；RuntimeDocument 不提供通用项目级文本/列表/事件 API | **部分解决**：新增 transient Canvas 的矩形、边框、直线、文本、裁剪；命令和字符串由宿主复制，最多 65536 条 | 正式保留式 UI 应提供字符串绑定、命令事件、动态列表、滚动与焦点管理；Canvas 不能替代无障碍控件树 |
| E04 / P0 游戏存档接口 | `SceneRuntime::snapshot()` 仅包含 ECS/场景；System 的 vector、deque、在途货物、科研预留不会保存，恢复会重新 create System | **游戏侧绕行**：独立保存完整领域模型；不用 runtime.save 作为工厂存档 | 引擎增加模块存档回调、版本迁移和事务恢复；验收应包含在途货物+制作队列保存后确定性续跑 |
| E05 / P1 通用持久化服务 | SDK 无用户数据路径、原子文件写入、错误查询服务 | **游戏侧绕行**：save.cpp 使用 Windows 用户数据目录、临时文件+MoveFileExW、校验后安装 | 把路径/原子替换/备份/单写者锁归入平台服务；目前同时打开两份游戏仍可能最后写入者覆盖存档 |
| E06 / P0 后台运行策略 | 原 Player::needsFrame 与 frame 都限制前台运行；挂机工厂切出窗口即停止 | **已解决基本后台模拟**；最小化保留模拟，停止画面提交，降低轮询频率 | 后续明确可配置的后台运行/暂停策略；FixedStep 的最长补帧仍会丢弃严重卡顿时间，不等同精确墙钟挂机 |
| E07 / P1 视口输入与缩放 | 渲染采用设计尺寸+留黑，而 OS 鼠标是窗口客户区坐标；未统一就会点错 | **已解决**：共用按设计尺寸反算坐标的宿主代码；画布和 HUD 使用同一基准 | 继续覆盖多屏 DPI、编辑器停靠布局、全屏、安全区域；本次不声称移动端自适应 |
| E08 / P1 模态与命中系统 | SDK 没有 UI 输入捕获/事件传播。实测科技页抢走制造弹窗按钮 | **游戏侧修复**：弹窗显示时抑制背后控件输入 | 引擎提供层级命中、pointer capture、modal root、快捷键上下文，避免每个项目重写 |
| E09 / P1 渲染批次 | 初始工厂自动渲染：332 条 Canvas 命令、432 个四边形、142 次 draw；背景/文本交错造成频繁纹理切换 | **已测量，未改排序算法**；游戏对画布节点做视口裁剪 | 保持遮挡正确的前提下批处理 UI，减少文字/纯色交错切换；用相同场景图对比 draw、CPU/GPU 时间，不能只报实体数 |
| E10 / P1 文本缓存 | `renderer.cpp` 按整段文本缓存，数值变动可能生成大量字符串纹理；只有纯整数走数字图集 | **未扩展缓存机制**；界面只保留必要精度 | 支持稳定文本分段、可复用 glyph atlas、显存页回收；需长时间挂机而非单帧验证 |
| E11 / P1 原生模块调试 | CLI 无法驱动键鼠或查看动态 Canvas，--check 只做一次加载/更新 | **已补充** runtime.input / runtime.canvas 与 gm_scene_capture | 新工具输出属于本程序 GPU 渲染，非桌面截图；完整 OS 输入路径仍需真机验证 |
| E12 / P1 窗口默认大小 | Player 固定 960×600，1600×900 的工厂 UI 被缩得过小 | **已解决默认大小**：由场景尺寸和工作区推导初始窗口 | 缺少项目级最小窗口/字体缩放/布局容器；当前 UI 仍为固定比例缩放 |
| E13 / P1 SDK 兼容发布 | Frame、Api 新增成员，旧模块不能继续按原布局读取 | **明确升级 ABI 9**，引擎版本 0.8.3；使用隔离 SDK 发布，未覆盖原安装 | 后续采用 feature/version 查询与可扩展结构长度，减少所有模块被迫重编译的范围 |
| E14 / P1 领域状态可观察性 | ECS stats 只看到工厂控制实体，不能代表模块内部建筑/物流内存和耗时分解 | **部分解决**：dsp.Metrics 暴露节点、线路、电力、科研、戴森数量；总 System 时间可查 | 自定义计数器、子阶段 profiler marker、模块私有内存统计；不能把 ECS componentBytes 当成游戏总内存 |
| E15 / P1 大规模任务 | 当前 SDK 不暴露任务池，不能安全地从游戏工作线程访问 World | **游戏侧有界处理**：离线最多 2h，每次宿主 tick 补 40 个模拟步，完成后再保存 | 提供纯数据后台任务+主线程提交模型；现阶段游戏仍串行，未宣称 ECS 自动并行 |
| E16 / P2 项目内容数据管线 | 场景/图像导入完备，但没有通用的表格/配方二进制资源类型 | **构建期转换** TS 目录 → C++ 常量目录 | 增加有 schema 的内容表编译、引用检查和热重载，避免每次改数值都链接 DLL |
| E17 / P2 音频 | SDK 无音效/音乐播放、音量总线或生命周期接口 | **未实现音频**，不以 Windows 临时蜂鸣器替代 | 引擎提供音频资源与播放句柄后再加建造/科研提示音 |

## 不应归咎于引擎的问题

- 配方预留、材料守恒、同一份货物唯一归属和科技条件是游戏规则，应在游戏模拟器测试。
- 初版游戏每条物流线线性寻找节点是本次游戏代码的问题，已改为每步构建 ID 索引；不能把这个 O(E×V) 问题称为 Flecs 或 bgfx 性能不足。
- 本次用独立领域容器保存生产网络，并以原生 System 驱动、以 ECS 指标暴露运行信息。并未把每个工厂节点都映射为 ECS 实体，因此本次工厂压力数据不是 ECS 性能基准。
- 云账号、排行榜、22 行星、蓝图、MOD、无限科研和全星系空间站属于参考游戏的更大范围，未完成不等于当前引擎存在相同名称的缺陷。

## 验证与边界

验证脚本在游戏工程 `tools/verify.ps1`，游戏的详细覆盖对照和操作方式见同目录 `README.md` 与 `docs/feature-parity.md`。测试输出、原生渲染截图均保存在游戏 `docs/` / `build/`。

- 引擎 CTest：10 组，覆盖原有生命周期/空间/UI/图像/渲染/后台任务和新增输入画布契约。
- 游戏最终 **351 项断言通过**，包含扩建预留、射线接收、禁止手工精炼、并联火电燃料与并联戴森发射等回归。最近一次 1000 台机器 / 100 个模拟步总耗时 44.967 ms，仅代表模拟 CPU 耗时。
- 已实际打开原生 Player，检查最大化、R 制造目录、科技页和中文文本。最终交互结果单独写入游戏验收记录，不能由截图推断玩法正确。
- `gm_scene_capture` 使用相同 Game.dll、SceneRuntime、SceneView 和 bgfx D3D11，能够在不操作桌面的情况下导出确定性画面。
- 正式 Player 只加载二进制入口场景与 C++ 模块；参考 React 页面没有嵌入游戏。

优先顺序建议：正式游戏 UI / 输入上下文 → 模块存档和平台持久化 → 性能可观察性与文本批处理 → 后台任务提交模型 → 内容表资源与音频。
