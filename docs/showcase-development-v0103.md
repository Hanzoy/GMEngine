## 已修复和已落地的改进

1. **屏幕 Canvas 被世界后处理污染。** 在 3D 场景中，文字被曝光/Bloom/FXAA 处理，低分辨率世界目标还会降低 HUD 清晰度。将世界后处理结束点提前至 Canvas 之前，屏幕 Canvas 与原有 HUD 都以原生输出分辨率合成。`world_renderer_contract` 比较开启/关闭后处理的实色面板和文字像素，覆盖曝光 4、Bloom、FXAA、renderScale 0.5，要求完全相同。
2. **原截图工具不适合性能结论。** 原先只有少数预热帧且开启 VSync。本次为 `gm_scene_capture` 增加显式输入配置、预热、逐帧模拟、关闭 VSync、CPU/GPU 分位数、唯一 GPU 帧去重及硬件编号记录。GPU 查询是延迟结果，不与当前 CPU 帧伪配对。
3. **复杂内容依然保持独立模块。** 两个游戏只 include 公开 SDK，不复制引擎/Flecs 内部实现；组件描述可由编辑器和 CLI 同时读取，最终 Player 使用二进制场景与 DLL。
4. **有界特效和资源共享。** 2D 敌人使用 33 个池槽，子弹上限 1400、爆炸粒子上限 3600；3D 使用共享网格/材质和最多 2400 个微粒。压力模式可关闭，重启不叠加对象。2D 星点默认 260、极高 620、压力 2400；3D 对应 360、900、2400。
5. **资源复现与发布。** 下载记录来源、作者、许可、校验和；网格/场景/音频生成器固定参数和种子。发布包从无关工作目录通过 `--check`，实际 Windows 窗口可启动和进入游戏。

## 开发中遇到的问题与处理

| 问题 / 复现条件 | 本次处理 | 后续建议 |
| --- | --- | --- |
| 自定义 Shader 使用 `line` 局部变量，D3D 编译失败 | 改为 `filament`，保留 shaderc 原始诊断 | Shader 面板跳到出错文件行；增加常见保留字诊断和多后端编译 CI |
| 通用材质参数名未在自定义 Shader 反射中出现 | 自定义材质只声明自己实际用到的参数；不携带 lit 参数 | 编辑器由反射生成参数表，编译前标出不存在的 uniform |
| 新组件场景字段不能省略 | 生成器为每个组件写完整字段和版本 | 文本导入可提供显式默认值迁移；不能静默接受拼错字段 |
| 起初整条步道把照片纹理拉伸到宽扁网格 | 改为几何镶嵌和独立地砖材质 | UV 密度检查、Triplanar 选项、可视化导入预览 |
| 晶体过强的自发光抹掉表面形状 | 核心晶体降低发光，保留高光与法线明暗；灯光与 UI 分层 | 曝光调试视图、直方图、亮度单位与材质预览 |
| 3D 摄影模式提前 return，导致重启也失效 | HUD 绘制条件与游戏操作分离；加入回归 | 引擎提供 UI 可见性层级，不应让显示开关阻断游戏逻辑 |
| 只加网格数量不能改善无阴影/无环境反射的观感 | 保留受控规模，用人工接触暗斑辅助，明确标记替代方案 | 优先实现阴影和 IBL，再扩展场景规模 |
| 合成音频在 headless 会话不自动推进 | 测试模式每固定帧调用音频离线 render，回收结束的 voice | 为 SDK 提供通用 headless 音频测试样例；目前音频初始化仍在首帧 |
| 编辑器不运行游戏 System，初始场景中全部 2400 微粒同时显示 | 源场景默认只启用 360 个，运行后由画质控制；保持编辑与默认游戏观感接近 | 大场景层级分组、可见性集合和独立编辑预览档位 |
| 高频更新数字容易引发字形缓存变化 | HUD 显示稳定标签和有意义的整数，保留文本统计 | 字形图集、动态文本布局缓存；先测缓存抖动再扩容 |
| 手工造场景需要处理大量路径、组件完整字段、材质约束 | 生成器 + 项目内说明 + CLI 玩法测试 | 场景层级分组、预制体批量操作、材质/Shader/OBJ 预览 |
| 图片生成返回尺寸低于预期高分辨率 | 保留原始文件、记录真实尺寸；没有声称 4K 源资产 | 后续安排专门美术高分辨率产出、拆分景深层；当前 4K 是输出尺寸 |
| UI 设计数据库没有匹配的原生游戏 HUD 模板 | 仅采用可读性/对比度原则，自行设计游戏界面 | 为原生游戏 HUD 加入尺度、焦点、操控和安全区规则 |

## 性能验证

硬件：Windows 11 26200、i9-14900K、RTX 4090 D，D3D11，Release。设备 ID 9861，厂商 ID 4318。CPU 内存约 64 GB。每组预热 60 帧、采样 240 帧，固定模拟 1/60 秒；关闭 VSync，GPU 延迟样本按帧号去重；音频采用 headless 离线混音。各组串行执行。

| 游戏 / 档位 | 输出 | 模拟 CPU p50 ms | GPU p50 ms | GPU p95 ms |
| --- | --- | ---: | ---: | ---: |
| 2D 高 | 1920×1080 | 0.048 | 0.063 | 0.101 |
| 2D 极高 | 1920×1080 | 0.049 | 0.068 | 0.128 |
| 2D 压力 | 1920×1080 | 0.099 | 0.083 | 0.137 |
| 2D 极高 | 3840×2160 | 0.052 | 0.133 | 0.473 |
| 3D 性能 | 1920×1080 | 1.021 | 0.228 | 0.295 |
| 3D 高 | 1920×1080 | 1.031 | 0.305 | 0.371 |
| 3D 极高 | 1920×1080 | 1.034 | 0.315 | 0.426 |
| 3D 压力 | 1920×1080 | 1.036 | 0.333 | 0.400 |
| 3D 极高 | 3840×2160 | 1.029 | 0.712 | 1.097 |

3D 极高参考帧约 **138.6 万三角形、1726 个实例、65 次 mesh draw**；压力参考帧约 **147.4 万三角形、3099 个实例**。所有三角形数包含重复实例，并非独特模型面数。2D 参考帧为 5 次 draw，压力为 7 次；诊断里的 `triangles` 当前只统计 mesh，不含 2D quad，不能误读为 2D 没有 GPU 工作。

这些是隐藏渲染表面的测量，**不是实际显示 FPS，也不是可承诺的最低配置**。短基准不包含首次导入/Shader 编译、设备长期温度变化、完整战斗最坏帧、手机、核显或开放世界流送。本次没有推导“比 Unity/Unreal 快多少”，没有测到引擎硬极限。程序还保留了资源块 128 MiB 等限制，因此用户允许 100 GB 并不意味着当前引擎能一次载入 100 GB 场景。源码、缓存、发布包和截图的真实体积另见游戏工作区报告。

当前 3D 模拟/提取约 1 ms，明显高于此场景 GPU 时间；下一步性能工作应先拆分动态变换与静态提取耗时，检查对 3427 实体的全量遍历。无需仅为这些小样例把游戏 System 复杂化为多线程。

原始结果：`docs/validation/showcase-performance-v0103.json`；玩法结果：`docs/validation/showcase-gameplay-v0103.json`。所有截图和输入配置保留在两个项目 `docs/`。复现工具为游戏工作区 `tools/benchmark-showcases.py` 和 `tools/verify-showcases.py`，引擎截图工具还支持旧的命令数组格式。

## 下一阶段建议及验收标准

| 优先级 | 工作 | 验收标准 |
| --- | --- | --- |
| P0 画面基础 | 方向光阴影（先单级，再 CSM）、bias/normal bias、PCF | 本场景柱廊/角色/地面有稳定接触关系；移动镜头无明显阴影抖动；HUD 像素仍稳定 |
| P0 材质 | HDR 天空环境、IBL 预过滤、BRDF LUT、反射探针 | 金属和粗糙石材随环境产生可辨别响应；有离线构建/内存统计/跨平台回退 |
| P0 工作流 | Shader/材质预览与错误定位；公开动态材质实例参数 | 不重编场景即可改变 time/tint；水面可真实动画；多实体共享基础材质但参数独立 |
| P1 几何 | glTF 导入、切线、子网格、材质槽、LOD | 能稳定导入许可明确的完整模型；法线方向正确；LOD 切换像素和容量测试可复现 |
| P1 CPU | 静态/动态变换标记、脏区域提取、查询与动画批处理 | 相同场景/相同像素输出下，报告模拟/提取 p50/p95 的前后对照；避免只减少测试内容 |
| P1 特效 | 实例化粒子、曲线、发射器、世界/屏幕分层、混合模式 | 视觉不依赖手写 Canvas 线条；明确上限、剔除、溢出和 GPU 资源回收测试 |
| P1 后处理 | SSAO、雾、颜色分级、可选抗锯齿方案 | 可切档；各效果前后帧耗时/显存独立测量；不污染 HUD |
| P1 内容流送 | 可分块场景、共享资源包、异步上传和卸载预算 | 超过当前单资源块限制仍可增量加载；记录峰值内存和阻塞帧，不只放宽上限 |
| P1 控制 | 3D 胶囊碰撞、导航/拾取；原始鼠标相对移动 | 镜头不穿墙，右键转向不受桌面边缘影响；保持编辑相机与游戏控制独立 |
| P2 验证平台 | 笔记本核显、Android 真机；随后 iOS | 发布包实际启动、温度/内存/帧时间长测；纹理格式与 Shader 后端一起验证 |
| P2 场景种类 | 骨骼人物、大规模战斗、动态昼夜、流式开放场景 | 使用独立项目复现，不能用本次静态建筑场景代表所有游戏性能 |
